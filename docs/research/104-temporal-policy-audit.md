# Current temporal policy path

The current branch provides a windowed MLP and a windowed GRU, plus a Controls-v2 transport and Physics bridge. It lacks a learned state that persists between canonical ticks and a frozen held-out visual score for selecting a trunk. [#104](https://github.com/rhythmatician/FractalSync/issues/104) can record its current-path audit, with architecture selection still open. The inspected source was 0431082.

## Train, export and run

| Stage | Current behavior |
| --- | --- |
| Input | The dataset decodes native-rate PCM into the Rust AnalysisTimebase and stacks the emitted feature windows. The default is ten frame-major frames by six features, one 60-value row per canonical 1024-sample hop at 48 kHz. The dataset keeps feature rows; the trainer adds file IDs and computes normalization from its training corpus. CycleBank state, named AudioActivation, Map, Physics and Julia view are absent from model inputs. [Dataset](../../backend/src/data_loader.py#L178), [training setup](../../backend/train.py#L524), [normalization](../../backend/src/control_trainer.py#L1841). |
| Learned trunk | AudioToControlModel defaults to a flattened MLP. The recurrent CLI option encodes each feature frame, runs a GRU across that window with implicit zero initial state, and passes its final state to the heads. The forward signature accepts only the current window and emits only controls. Clip batching groups adjacent same-file windows for sequence losses, shuffles clips, and flattens them into separate model examples. That context does not persist learned state across inference calls or training chunks. [GRU and forward](../../backend/src/control_model.py#L200), [clip batching](../../backend/src/control_trainer.py#L1091), [forward call](../../backend/src/control_trainer.py#L1239). |
| Outputs and training rollout | The CLI defaults to legacy orbit-control outputs. Opting into controls/2 emits a Rust-defined 13-channel schema. The Controls-v2 batch path calls native motion integration at the canonical hop with a straight-through backward surrogate. It samples initial positions per file ID within the batch, starts each sequence call at rest, and resets on changes of file ID. Adjacent shuffled clips from the same file can share a file ID after flattening. The loop therefore supplies a useful bridge test but leaves chronological rollout/checkpoint reset semantics open. The batch path parses view deltas, then sets them aside and skips legacy rendering. [CLI](../../backend/train.py#L403), [Rust schema](../../runtime-core/src/model_io.rs#L85), [Controls batch](../../backend/src/control_trainer.py#L1287), [Rust forward and surrogate](../../backend/src/cspace_proxies.py#L1244), [sequence resets](../../backend/src/cspace_proxies.py#L1358). |
| Export | The direct exporter writes one ONNX input called audio_features and one output called visual_parameters, with dynamic batch size. It uses the legacy exporter for recurrent modules. The direct training metadata stamps feature, controller, analysis, model type and, for controls/2, Controls versions. There is no AudioActivation, PlayerObservation or recurrent-state schema stamp. The separate checkpoint loader constructs the default model and does not recover a recurrent or Controls-v2 architecture choice. [ONNX export](../../backend/src/export_model.py#L36), [training metadata](../../backend/train.py#L653), [checkpoint loader](../../backend/utils/checkpoint_loader.py#L84). |
| Browser | ModelInference serializes asynchronous ticks in arrival order, normalizes tick.features, runs the single-input/single-output ONNX session, and selects the Rust decoder from metadata. Under controls/2 it steps Rust Physics using the tick duration and applies view deltas to persistent JuliaViewState once per processed tick. The audio capture resets and disposes its timebase on stop. ModelInference neither carries learned state nor handles streamEpoch as an inference reset or queue invalidation. Loading a model initializes Physics and view state. The model and metadata endpoints choose their latest files independently by modification time. [Model load](../../frontend/src/lib/modelInference.ts#L169), [tick queue and inference](../../frontend/src/lib/modelInference.ts#L329), [capture reset](../../frontend/src/components/AudioCapture.tsx#L132), [artifact endpoints](../../backend/api/server.py#L30). |

The Rust output schema, named decoding and canonical clock/wiring can carry forward. The legacy orbit heads, visual parser, orbit rollout and current window-specific learning path are comparison or migration code. The Controls-v2 bridge still has input and training assumptions that belong to the current model, including a positional packed feature window, trainer offsets for audio statistics, and positional ONNX port names. The audited local metadata files in checkpoints, backend/checkpoints and frontend/public contained 43 orbit-control, four step-control and five unstamped model types. None of the 52 had a controls/2 or analysis-pipeline stamp. This local inventory supplies no matched destination checkpoint pair.

## Visual outcome and remaining decision

The current trainer's best-checkpoint proxy is the negative sum of training sequence-perceptual and hit-alignment losses. The Controls-v2 branch also scores correlations between audio cues and motion proxies, despite names that refer to color. These are training diagnostics. The [frozen renderer probe](151-frozen-julia-sensitivity.md) measures seed sensitivity, the [calibration panel](171-julia-sensitivity-calibration.md) still leaves Julia derivative regimes unresolved, and [#140 morphology evidence](140-julia-morphology-provenance.md) identifies confounds in candidate descriptors. The [#189 protocol](189-expressive-dynamics-protocol.md) separates audio task performance from subjective fit and has no listener result. These tests inform score design. A frozen primary visual score tied to held-out Player behavior and a matching reset schedule still need to be declared. [Current checkpoint selection](../../backend/src/control_trainer.py#L1896).

The matched experiment needs the versioned [#108 observation](https://github.com/rhythmatician/FractalSync/issues/108), a named [#109 audio candidate](https://github.com/rhythmatician/FractalSync/issues/109) for prototypes and the final tensor for acceptance, and the chronological [#130/#132 training path](https://github.com/rhythmatician/FractalSync/issues/130) with fixed [#110 reset policies](https://github.com/rhythmatician/FractalSync/issues/110). It also needs a persistently stateful comparator with explicit ONNX state ports and rules for epoch changes, resets, skipped display frames, and training chunk boundaries. Specify parameter and inference budgets before the matched trial. Keep deterministic world, analysis and presentation state in Rust. Export only the product action and any learned state the runtime needs. Training-only teacher heads can be evaluated separately after a no-teacher comparison. The [#111 cockpit](https://github.com/rhythmatician/FractalSync/issues/111) can record scripted Controls now, while frozen-checkpoint policy playback and held-out visual judgments remain acceptance work.
